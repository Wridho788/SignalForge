## M0 — Repository reconnaissance and project contract
**Status:** DONE. Reconnaissance, pnpm scaffold, scripts, `.env.example`, baseline, ADRs 0001–0005 accepted, git initialised (no commits made), secret-pattern scan clean, install/lint/typecheck/test/build/E2E verified from a clean export.

**Deliverables**
- Inspect current repository, runtime, package manager, dependency versions, and conventions.
- Establish `AGENTS.md`, scripts, environment examples, lint/typecheck/test baseline.
- Confirm local data directory and local-only startup behavior.

**Acceptance**
- Clean install/build works from documented steps.
- Baseline failures are recorded separately from new regressions.
- No secrets committed.

## M1 — App shell and database foundation
**Deliverables**
- App layout, navigation, design tokens, reusable form/table/feedback components.
- SQLite connection, migrations, repository layer, settings.
- Health endpoint and error boundary.

**Acceptance**
- App binds to loopback.
- Migrations and basic repository tests pass.
- Empty states are usable and responsive.

## M2 — Episodes and distributions
**Deliverables**
- Episode CRUD and tags.
- Distribution CRUD for Facebook, YouTube, TikTok.
- Episode detail with platform-specific distribution list.

**Acceptance**
- Validation and duplicate rules work.
- Dates render in selected timezone.
- Unit/integration/E2E tests cover critical CRUD paths.

## M3 — Metrics and snapshots
**Deliverables**
- Configurable metric definitions.
- Append-only snapshots and values.
- Snapshot timeline and manual entry UX.

**Acceptance**
- Unknown and zero stay distinct.
- Platform-specific metric fields are supported.
- Irregular/missing history is clearly represented.

## M4 — Analytics dashboard
**Deliverables**
- Overview KPIs, trend charts, filters, sortable table.
- Equivalent-age comparisons and completeness warnings.
- Episode performance detail.

**Acceptance**
- All metrics have units and observation context.
- Incompatible values are not silently combined.
- Null/zero, age-window and baseline tests pass.

## M5 — Experiments
**Deliverables**
- Hypothesis/variable/success criteria form.
- Link distributions and record outcomes.
- Experiment history and decision log.

**Acceptance**
- Experiments can be inconclusive.
- No causal claims are generated by simple before/after comparison alone.

## M6 — Import/export and backup
**Deliverables**
- CSV template/download, preview, row validation, duplicate resolution.
- CSV export and database backup/restore instructions.

**Acceptance**
- Invalid import cannot partially commit silently.
- CSV formula injection mitigation implemented.
- Backup/restore and round-trip tests pass.

## M7 — AI Connections and analysis
**Deliverables**
- AI Connections page for Claude and Codex.
- Provider status, official login/setup flow, test connection, safe errors.
- Opt-in data preview and bounded analysis response.
- Findings/evidence/limitations/hypotheses/experiment format.

**Acceptance**
- Core app functions with both providers offline.
- Official authentication is used; no token textbox or token display.
- Timeout/cancel/rate-limit/auth errors tested.
- Current provider documentation and usage restrictions rechecked.

## M8 — Hardening and MVP release
**Deliverables**
- Accessibility and responsive pass.
- Security review, performance check, logs/diagnostics scrubbed.
- README, data location, backup/restore, troubleshooting, release notes.

**Acceptance**
- All release gates in `docs/testing/QUALITY_GATES.md` pass or have explicitly approved exceptions.
- Fresh setup verified from clean checkout.
- Known limitations documented.

## Suggested implementation order
Do not implement AI first. Establish correct metric data semantics and analytics before AI, otherwise the model will summarize unreliable data. AI Connections can be scaffolded early, but inference should be integrated after typed analysis summaries and tests exist.
